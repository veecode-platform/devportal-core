# DevPortal 3.1.0 release notes

DevPortal 3.1.0 moves the image from Backstage 1.52 to Backstage 1.54.9 and stays on the old frontend system. This page lists what changes for an operator upgrading from 3.0.x, what to check and what to edit before the upgrade. Items marked "to confirm" are not verified yet.

## Backstage 1.54.9 on the old frontend system

3.1.0 runs Backstage 1.54.9, up from 1.52 in 3.0.x. It is built from RHDH commit `3ac14d77`, the last RHDH `main` commit before RHDH moved its app to the new frontend system. The move to the new frontend system is planned for v4.

The base images move from UBI 9.8 to UBI 10.2 and Node.js from 24.19.0 to 24.21.0. The dynamic plugin installer moves from 0.4.1 to 0.5.0. If a derived image or an init script assumes UBI 9 packages or paths, check it against UBI 10.

The release candidate is `docker.io/veecode/devportal:3.1.0-rc.1`. Its manifest list digest is `sha256:9ce2cbeb4cd744297ce5db236f7fa25adca979ec44599fcaa92a1a60814cb01d` and it covers `linux/amd64` and `linux/arm64`. The `3.1.0` tag is promoted from the approved candidate by digest, without a rebuild (to confirm at release).

## Plugins that are no longer in the image

The 3.1.0 image has no `dynamic-plugins/` directory. RHDH removed its local plugin wrappers upstream, and this line carries the removal. The 3.0.3 image has 41 directories under `dynamic-plugins/dist/`.

An entry keyed by a former `./dynamic-plugins/dist/...` path is not an error. In a run of the 3.1.0-rc.1 installer with two such entries, it logged `Skipping 2 local plugins (directories not found)`, named each path, reported `All plugins installed successfully` and exited 0. The plugin is silently missing. The 3.0.3 installer installs the same entries and logs `Installing NPM plugin ./dynamic-plugins/dist/...` for each.

Before you upgrade, search `global.dynamic.plugins` and any `dynamic-plugins.yaml` you mount for `./dynamic-plugins/dist/`. Search the Marketplace selections too. The Marketplace stores them in the `marketplace_installations` table, and a row whose `package_name` is a former local path reaches the installer unchanged and is skipped the same way.

Replace each entry with the plugin's OCI reference, or remove it. [Installing Plugins](../dynamic-plugins/installing-plugins.md#loading-a-plugin-from-an-oci-image) describes the `oci://` form. Of the 146 packages in the 3.0.x catalog index (`bs_1.52.0`), 135 use OCI references and eleven use a `./dynamic-plugins/dist/...` path. Those eleven cover eight plugins: acr, adoption-insights, bulk-import, keycloak, pingidentity, quickstart, scaffolder-relation-processor and topology. A Marketplace selection of one of them made on 3.0.x is expected to be keyed by the local path and to stop loading on 3.1.0 (to confirm). The 3.1 catalog index is expected to offer all eight as OCI images (to confirm: that index is not published yet).

The product face is not affected: its 20 entries are already pinned to OCI artifacts. [Product face overrides](3.0.0.md#product-face-overrides) in the 3.0.0 notes describes the same effect for overrides of the face.

## Security fixes

3.1.0 locks `@backstage/plugin-scaffolder-backend` 4.1.0, which fixes GHSA-g2v8-7jhw-pp8p (critical, sensitive information exposure in the Scaffolder). 3.0.3 ships 4.0.1, which is in the affected range.

multer moves from 2.3.0 to 2.4.0, which fixes GHSA-3pph-fpjx-jg34 (medium, denial of service through orphaned disk writes on aborted uploads).

proxy-addr stays at 2.0.8, the fix for GHSA-jqcg-44mw-7w3h (critical, IP spoofing through an IPv4-mapped IPv6 trust subnet). The 3.0.3 host already resolved 2.0.8. RHDH's lock resolves 2.0.7, so 3.1.0 pins 2.0.8 with a `package.json` resolution.

## Versions kept at their 3.0.x levels

`@backstage-community/plugin-rbac-backend` stays at 7.12.5 and `@red-hat-developer-hub/backstage-plugin-translations-backend` at 0.3.1. rbac-backend 8 refuses the conditional-policy writes of the RBAC frontend the image ships, so the move to 8 waits for the RBAC frontend 2.x.

`@scalprum/core` 0.9.3 and `@scalprum/react-core` 0.11.2 stay pinned with resolutions, although the app declares 0.10.3 and 0.13.3. Removing the pins changes the plugin host runtime.

## Plugin catalog index

3.1 is meant to ship with a plugin catalog index built for Backstage 1.54.9 (`bs_1.54.9`). That index is not published yet. On 2026-10-14 the newest `quay.io/veecode/plugin-catalog-index` tags were `bs_1.52.0` and its timestamped variants. The overlays pull request that builds the new index, [devportal-plugin-export-overlays#287](https://github.com/veecode-platform/devportal-plugin-export-overlays/pull/287), is a draft. This section follows that draft at head `c3a33c13` and can change before release (to confirm).

Until the 3.1 index exists, image 3.1.0 on chart 1.0.4 runs with the `bs_1.52.0` index that the chart pins by digest. Those plugins are built for Backstage 1.52 and the host is 1.54.9. That combination is not verified yet (to confirm).

The draft moves these plugins to a new major version, from the 3.0.x index to the draft 3.1 index: argocd 2.8.0 to 3.1.3, rbac frontend 1.52.4 to 2.3.1, tekton 3.37.0 to 4.0.5, jfrog-artifactory 1.30.0 to 2.0.3, multi-source-security-viewer 0.15.2 to 1.0.3, analytics-provider-segment 1.27.0 to 2.0.0, global-header 1.21.6 to 3.1.0, github-actions 0.22.0, github-deployments 0.18.0, github-discussions 0.10.0 and github-pull-requests-board 0.16.0 to 1.4.0, tech-insights-backend 2.5.0 to 3.1.0, topology 2.12.3 to 3.0.7, bulk-import 7.3.5 to 9.1.1, quickstart 1.9.6 to 2.2.0 and adoption-insights 0.8.2 to 1.0.4.

The RBAC frontend and global-header are also product face plugins. The version that loads is the one pinned in the face baked into the image, and in 3.1.0-rc.1 that is the 3.0.3 pin: RBAC frontend 1.52.4 and global-header 1.21.6. The index version is the one the Marketplace shows. Whether the face moves to `bs_1.54.9` builds before release is not decided yet (to confirm).

Most of these majors make the new frontend system plugin the default export of the package and move the old exports to a `/legacy` subpath: argocd 3.0.0, rbac 2.0.0, tekton 4.0.0, jfrog-artifactory 2.0.0, multi-source-security-viewer 1.0.0, analytics-provider-segment 2.0.0, topology 3.0.0, bulk-import 8.0.0, quickstart 2.0.0 and adoption-insights 1.0.0. The changelogs describe this as a change of import paths for an app that compiles the packages in. The portal runs the old frontend system, so the draft adds a `scalprum-config.json` to each of these workspaces that sets `PluginRoot`, the default module, to the legacy entry. The draft's notes say that without it a missing export shows only as a console warning and the plugin does not render. The draft default configuration of tekton also names `module: Alpha` for its translation resource. If you override `pluginConfig` for one of these plugins, compare it with the default of the new version. Whether the exported bundles load in the portal is not verified yet (to confirm).

Four moves have notes of their own.

The azure-devops backend moves from 0.27.0 to 0.32.0. When `azureDevOps` is set, its config schema requires `azureDevOps.pullRequestDashboard.organizations`, a list of entries with `organization` and `host`. Add it before the upgrade (to confirm the startup failure when it is missing):

```yaml
azureDevOps:
  pullRequestDashboard:
    organizations:
      - organization: <your organization>
        host: dev.azure.com
```

The four GitHub plugins move from Material UI to Backstage UI (upstream 1.0.0). The host app ships `@backstage/ui` 0.17.1.

bulk-import-backend 9.0.0 requires short-lived GitHub App installation tokens for the Orchestrator import mode, and fails closed when only a classic personal access token is available.

tech-insights-backend 3.1.0 has no documented breaking change. The upstream 3.0.1 notes say "No breaking changes" and replace a 3.0.0 that crashed on startup.

The draft keeps global-header at 3.1.0, the last version with a legacy entry. Upstream 3.2.0 removes the `/legacy` export and the legacy frontend plugin implementation. It also keeps app-auth and app-integrations at 0.0.2, the version in the 3.0.x index.

## Chart

The chart that ships 3.1.0 is devportal-chart 1.1.0 (to confirm: it is not released yet). The latest chart release is 1.0.4. It installs image 3.0.3 and pins the `bs_1.52.0` catalog index by digest. The chart re-pins the index at each release, so chart 1.1.0 is expected to pin the `bs_1.54.9` index (to confirm). See the chart's [catalog index configuration](https://github.com/veecode-platform/devportal-chart/blob/main/docs/catalog-index-configuration.md).

## Known issues

In 3.1.0-rc.1 the product face is the same file as in 3.0.3: both images carry it with the same sha256. Its 20 entries keep the digests they pinned in 3.0.3, built for Backstage 1.52.0 (the theme for 1.49.4), and they now run on a 1.54.9 host. A browser check of the face on that host has not been run yet (to confirm).

The 3.0.0 known issue about the Red Hat Home page entry is not re-tested on 3.1.0. The face still ships that entry disabled.

The release qualification of 3.1.0-rc.1 (install, Marketplace install, upgrade from the previous chart, restarts and rollback) is not verified yet (to confirm).

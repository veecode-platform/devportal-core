# DevPortal 3.0.0 release notes

## Product face overrides

DevPortal 3.0.0 pins all 20 product-face entries to OCI artifacts by digest. Eighteen are enabled by default; the stock Home page and legacy theme are disabled.

An override keyed by a former `./dynamic-plugins/dist/...` path no longer matches the moved face entry, so its default remains enabled. A beta.10 runtime check with an enabled Tech Radar override on its former local path and its own `pluginConfig` loaded both the local-path plugin and the OCI face plugin. Remove or migrate old-path overrides to the current full OCI reference to avoid loading a second copy. Use the current full OCI reference in `global.dynamic.plugins` to disable or reconfigure a face plugin.

A tag or digest in an override pins that artifact version. Update or remove the override when the face changes. See the [product face override guide](https://github.com/veecode-platform/devportal-chart/blob/main/docs/product-face-overrides.md).

## Known issues

The product face ships the Red Hat dynamic Home page entry disabled. Enabling it, for example from its Marketplace card, leaves the portal's pages empty: the frontend reports `duplicate or forbidden API factory`, because that plugin and the DevPortal home page register the same frontend API. Keep the entry disabled.
